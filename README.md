# Portland Housing Density Mapper

An interactive map of Portland-area taxlots, colored by zoned residential density (and by census tract /
census block, as alternate "view by" modes). Ships with a working data snapshot, so it runs immediately -
the scripts below only matter if you want to regenerate that data from scratch.

## Running it locally

Just serve the repo root over HTTP and open `portland-housing-density-mapper.html` - e.g.:

```
python3 -m http.server 8000
```

Taxlot mode will fail to load locally (it fetches `/taxlot-data` from a Cloudflare Worker + R2 binding that
only exists once deployed - see Deployment below). Zoning/tract/block modes work fine locally, reading
straight from the small `runtime-data/*.json.gz` files.

## Regenerating the data

Everything under `runtime-data/` is generated by the scripts in `scripts/`, run in this order:

1. `python3 scripts/build_mpa_boundary.py` - builds the Metropolitan Planning Area boundary polygon
   (`runtime-data/mpa_boundary.json`) that every later step clips to.
2. `python3 scripts/build_taxlot_dataset.py` - fetches every taxlot + zoning polygon in the region, clips to
   the MPA boundary, spatially joins each taxlot to its zoning class. Writes
   `runtime-data/taxlot_density_data.json(.gz)`.
3. `python3 scripts/fetch_taxlot_addresses.py` - enriches each taxlot with a real site address from Metro's
   Master Address File.
4. `python3 scripts/fetch_taxlot_housing_units.py` - enriches each taxlot with existing housing unit counts.
5. `python3 scripts/add_portland_rip_density.py` - computes Portland's Residential Infill Program max-unit
   allowance per taxlot (Portland City Code 33.110.265).
6. `python3 scripts/build_aggregation_layers.py` - builds the census tract / census block / zoning-polygon
   aggregate layers used by the map's other "view by" modes.

Steps 2-4 each take a while (hundreds of thousands of taxlots, paginated ArcGIS queries) and checkpoint
their progress into a `Non-essential data/` directory (create it first: `mkdir "Non-essential data"`) so a
killed/crashed run resumes instead of starting over. Checkpoints are gitignored - not canonical output, just
crash-recovery state.

## Deployment

This repo deploys as a single Cloudflare Worker (see `wrangler.jsonc`). The one wrinkle: the taxlot dataset
(~70MB uncompressed) is over Cloudflare Workers' 25MiB static-asset limit, so it's served instead from an R2
bucket via `workers/density-mapper-worker.js`, which is bound in `wrangler.jsonc` as `TAXLOT_DATA_BUCKET`.
Upload `runtime-data/taxlot_density_data.json.gz` (the gzip-compressed bytes, produced by
`write_taxlot_dataset()` in `build_taxlot_dataset.py`) to that bucket under the object key
`taxlot_density_data.json` (no `.gz` in the key - that's just what the Worker reads). The Worker streams
those gzip bytes as-is with a plain `application/octet-stream` content type; the browser-side
`workers/taxlot-parse-worker.js` decompresses them client-side via `DecompressionStream`.

Everything else deploys via `scripts/stage_deploy_assets.sh` (invoked automatically by `wrangler.jsonc`'s
`build.command`), which stages the HTML file, favicon, and the small `runtime-data/*.json.gz` layers into
`dist_assets/` as static assets.

Deploy with `wrangler deploy`, or connect this repo to Cloudflare Workers Builds (Workers & Pages -> Create
-> Connect to Git) for auto-deploy on every push.
